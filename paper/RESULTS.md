# Results: predictions, decisions and record

This page records what each prediction of the design came to and what the
author decided before drafting the paper. The predictions are those of spec
§5.4, written before any model ran. The spec is
`docs/superpowers/specs/2026-09-26-gricean-simulation-design.md`.

## How to use this page

- Write on the lines that end in a colon. The rest of the text can be
  edited too, except the tables.
- A verdict is `held`, `failed` or `mixed`. Leave the line empty while the
  claim is open.
- The tables are rewritten by `make report` or `uv run gricean results`.
  Anything typed inside a table is lost at the next run.
- `git log -p paper/RESULTS.md` shows when each verdict and decision was
  written.

Three things on this page were chosen after the results were known: the
split of the four predictions into twelve claims, the cells shown under each
prediction, and one sum, the row "All … categories" of the Line 1 tables.
The spec says so in its revision log (2026-11-21).

Before reading the tables:

- Line 1 is the response of each model as coded by the author. Line 2 is
  the log-odds of the intended over the literal continuation, with no coder.
- An English cell rests on eight items, or on two for the controls. A
  Portuguese cell rests on two items, or on one for the controls.
- The Line 2 intervals are per model. Two rungs are compared on the same
  items, not by whether their intervals overlap.
- "Table reading" under a claim means that no test compares the cells; the
  verdict is then a reading of the table.

## What no table tests

- No test compares one rung with another, on Line 1 or on Line 2. Every
  claim above that says a measure rises, holds or moves little rests on a
  reading of the table.
- No test compares data scales on `correct`. Spec §13.1 tested only whether
  the turn ended.
- Turn completion cannot be read past SFT on the official ladder while the
  limit is 150 tokens.
- The Line 2 table prints `share_neither` only, of the three shares.

A sentence in the paper that needs one of these first needs a new analysis:
the measure is committed before it is computed (`WORKFLOW.md` §7).

## Where the data comes from

The tables on this page are read from the files under `paper/olmo/` and
`paper/selfrun/`. Those files are regenerated from committed data, with no
model:

    make report                              # paper/olmo/, then this page
    uv run gricean report --ladder selfrun   # paper/selfrun/
    uv run gricean results                   # this page alone
    uv run gricean results --check           # says whether it is up to date

Tables that this page does not show:

| File (in each ladder's folder) | What it holds |
|---|---|
| `intent.csv` | Line 1 in full: `literal`, `intended` and `neither` |
| `logodds.csv` | Line 2 in full, with `share_neither` |
| `logodds_template_control.csv` | Line 2 for SFT, DPO and Instruct on raw text (official ladder only) |
| `correctness.csv` | The share coded `correct`, for `intended` and for `literal` responses |
| `termination.csv`, `termination_correctness.csv` | Turn completion by category and by code |
| `examples.md` | Responses drawn at random with a fixed seed |
| `ladder.png` | The figure |

Files ending in `_pt` are the Portuguese subset.

What fixes a run is held in these files, not copied here:
`stimuli/CHECKSUMS` (the frozen stimuli), `configs/models.yaml` (the model
revisions), `configs/generation.yaml` (decoding and seeds) and
`gricean.report.EXAMPLES` (the draw of the examples).
